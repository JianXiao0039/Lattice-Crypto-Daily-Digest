# Operational and scientific policy v1

Repository skill precedence and explicit user authorization apply. Codex is the
unique integration and release owner. External output is a proposal until audited.

1. Authority: read current Git root, HEAD, status, live origin/main, control files
   and task scope. Dirty development files are never copied into published runtime.
2. Math/definitions: distinguish source observation, paper identity, publication
   event, revision, historical restatement, coverage authority and scientific
   validation. Missing historical windows/health remain UNKNOWN, never inferred
   from nominal 36h. A restored report is not proof of a scheduled delivery.
3. Source/code: keep lattice cryptography central. Classify original source spans,
   never generated prose. Separate paper claims, model inference and hypotheses;
   keep author attribution and TODO_VERIFY for unverified security claims.
4. Tests: reproduce defects, use isolated candidate/test authority, preserve all
   failures, and verify real public Daily/Weekly/Monthly output writing plus
   structural, semantic, cross-day and durable QA. No fake tool executions or PASS.
5. Artifacts/reproducibility: hash inputs/outputs, snapshot exact original bytes,
   keep provider attempts and real observation times. Apply only hash-guarded,
   reversible repairs; preserve user annotations and sealed evidence. Cleanup
   preserves evidence and needs bounded ownership, not parent-directory sweeps.
6. SOTA/claims: verify references and keep claim/proof/experiment scope distinct.
   Do not inflate historical observations into new papers or generate unbounded
   AI+lattice ideas. Translation placeholders are incomplete translations.
7. Deployment: published independent Git checkout, explicit canonical root,
   import closure and manifests, clean runtime dependencies, exact nested runtime
   trust, and live remote provenance are mandatory. Update the same three existing
   automations only through supported API/UI; preserve schedules and scientific
   instructions. No second scheduler or fabricated scheduled receipt.
8. Privacy/safety: no secrets in evidence; no unrelated/private project access;
   no destructive Git, mass staging, force push or unauthorized remote mutation.
9. Token economy: inspect compact evidence first; reuse verified immutable inputs,
   batch independent reads and delegate bounded audits. Resolve proven defects
   once; do not repeatedly run the same blocked entry or duplicate large bundles.

Acceptance states are independent: CODE_READY, DEPLOYMENT_CONFIG_VERIFIED,
MANUAL_REPORT_GENERATED, SCHEDULED_REPORT_GENERATED. Overall closure requires
code, actual E2E, live deployment and all evidence-supported in-scope repairs.
